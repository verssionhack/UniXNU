# r101 A3: nTWE only (host preparation; no boot)

A3 uses the finalized A2 observer build and sets SCTLR_EL1.nTWE, bit 18. nTWI is preserved. No Data size, display, service, IPC, SMP, EPSS, trust, argument, ADT or keystore behavior changes are included. No trap-handler fallback is bundled. A2 must be captured first under a separate go; A3 requires another go after that result is reviewed. Neither image has been booted in this review session.

## Exact change and CPU paths

`out/liuqin-r101-a3-work/evidence/A2-to-A3.patch` adds one instruction to pinned `osfmk/arm64/start.s`:

```asm
Lq76AfterToken:
    orr x0, x0, #0x40000
    dsb sy
    MSR_SCTLR_EL1_X0
    isb sy
```

The OR is outside the optional EL0-access argument branch; it applies on entry to common_start from both cold start and secondary/reset paths (source branches at start.s:369 and :721). It precedes the existing barrier and SCTLR write. `proc_reg.h:SCTLR_EL1_REQUIRED` already includes `SCTLR_nTWE_WFE_ENABLED`; bit 16 is not added. Host source analysis establishes these paths; eight distinct CPU readbacks in the real run must establish the effective hardware state. Higher-EL trap routing is not changed or claimed ruled out by source alone.

Actual machine-code verification and artifact identities are generated by `verify.py` into `evidence/host-verification-a3.json`. Observer sources, device driver sources, args, ADT, trust, Data seed/capacity and critical execution/VM source are compared to A2. The const-VMA, segment caps, AES/fileset and payload readback gates must all pass. A3 has no independent observer additions.

## WFE wake source

**Host-verified cache bytes:** `_dispatch_wait_for_enqueuer` executes `ldxr x8,[x0]` at 0x1855af510, checks for a nonzero value, and executes WFE at 0x1855af518 on the zero path. It therefore establishes an exclusive reservation before waiting; this is not a bare WFE with no monitored location.

**Architecture:** a write to a shareable monitored location can clear the PE's global exclusive monitor, generating the event that wakes WFE. WFE is a hint, may return spuriously, and the algorithm rechecks its condition. The exclusive-monitor event mechanism supplies the intended wake source; enabling nTWE permits this normal EL0 sequence rather than translating a trapped WFE into SIGILL. This does not establish scheduler progress or the attributes of every live target mapping on this tablet. The actual A3 behavior remains unmeasured.

Reference: [Arm A-profile Architecture Reference Manual](https://developer.arm.com/documentation/ddi0487/latest), WFE wake-up events and exclusive monitors. The [WFE instruction/pseudocode mirror](https://finkmartin.com/aarch64/wfe.html) and [shared pseudocode](https://finkmartin.com/aarch64/shared_pseudocode.html) are saved under A2 `evidence/review/` with source URL implied by filenames. In the latter, `ClearExclusiveByAddress` specifies clearing other PEs' global monitors on the written physical region and `Hint_WFE` checks events/trap routing. Those abstract pseudocode stubs alone are not a hardware wake test.

## Success measures fixed before either new capture

Use identical A2/A3 observers, nominal 480 s capture, the existing guards, fixed 120 s fastboot cooldown and actual host timestamps. Keep temperature marked unavailable unless a real source is found. The baseline is A2, not the differently instrumented A1; A1 remains historical evidence.

1. All eight per-CPU readbacks are present. A3 must show nTWE=1 on each CPU; compare other SCTLR bits, especially unchanged nTWI. Missing CPUs or another changed control bit prevent the intended one-variable interpretation.
2. Uncapped primary `ux_sig` EXC_BAD_INSTRUCTION/SIGILL/undefined instruction histogram must report **zero WFE-word events** in A3, with total, tracked/overflow and sample coverage shown. Missing/suppressed coverage or histogram overflow prevents a zero claim. If A2 happens to show zero too, the pair is uninformative about a rate reduction even if the architectural correction is established. EL0 TRAP=0 never means zero faults.
3. Report all EL0 fault classes under the frozen five-field rule, then ReportCrash cumulative/window CPU, exits, jetsam, ENOSPC, Data/free-memory series, physical block-writer windows and max_pid/pid growth. Present actual time windows and exit races; avoid subtracting unmatched cumulative sample times.
4. Compare below-16-MiB crossing brackets and the complete Data curve. Do not require the Data volume to stay free as a condition for the WFE register fix; other writers may still fill it. No Data increase is bundled, and A1's 106 MiB coarse minimum leaves inadequate evidence for an extra 512 MiB.
5. Prefix/walker begin/end markers, complete snapshot checksums and output/overflow budgets must pass. A walker panic/hang is an observer failure, not a userspace behavior result. A transport-gap/fence timeout skips native walking and is explicit coverage loss. A2 must first establish this observer pipeline on hardware.

No runtime success is claimed by this document. B remains optional and multi-variable. Owner-key disposition and testing the offline signing flow against the real key remain owner decisions; these preparations access neither.
